# WardSen v0.1.0-rc.49

Unsigned prerelease focused on safer credential delivery operations, recipient-link audit signals, employee request access, and release evidence.

This is a security-review prerelease, not a trusted public release. Windows and macOS installers remain unsigned until repository signing credentials and target-machine lifecycle checks are configured. Windows testers receive an MSI only; WardSen does not publish the previously removed unsigned NSIS setup EXE.

## Install Or Update

Windows:

1. Download `WardSen_0.1.0_x64_en-US.msi` from this release's assets.
2. Verify the checksum with `SHA256SUMS-windows-x64.txt`.
3. Run the MSI only if you trust this unsigned prerelease.
4. If Microsoft Defender blocks the MSI, leave it quarantined and report the detection details.

macOS:

1. Download the macOS DMG from this release's assets.
2. Open the DMG.
3. Drag WardSen into Applications.
4. Verify the DMG against `SHA256SUMS-macos-arm64.txt` before opening WardSen.
5. Do not bypass a Gatekeeper or `"WardSen" is damaged and can't be opened` warning with `xattr`, `sudo xattr` or another override. This unsigned prerelease is not suitable for normal macOS installation; report the Gatekeeper result with the installer checksum instead.

Provider setup:

1. Install the provider tool you want to use, such as Bitwarden CLI `bw` or KeePassXC.
2. On macOS, install Node.js LTS from [nodejs.org](https://nodejs.org/en/download) if `npm` is unavailable, then run `node -v && npm -v`.
3. Install Bitwarden's official CLI with `npm install -g @bitwarden/cli`, verify it with `bw --version`, then fully quit and reopen WardSen. Do not use a raw `bw` executable macOS cannot verify or bypass its quarantine.
4. If WardSen cannot find the tool, use the install guide and copyable help shown in the app.
5. For Bitwarden first login, use **Terminal login / unlock**, paste the copied command into Terminal or PowerShell, and wait for WardSen to update the account automatically. Enter the Bitwarden password, email/device approval code, authenticator code and session token only into the visible official Bitwarden CLI prompts, never into WardSen or a support message.

Optional verification:

1. Download the matching `SHA256SUMS-*.txt`, `RELEASE-MANIFEST-*.json` and `WARDSEN-SBOM-*.json` assets.
2. Compare the installer and SBOM checksums before opening the installer.

## Changes

- Added server-enforced exact confirmations for account deletion, hard person deletion, delivery revocation, batch-link revocation, and employee request replacement workflows. The API rejects destructive actions without their required confirmation phrase.
- Added recipient-link audit and leak-mitigation signals: first-seen access time, access-count/status refresh, unexpected-access warnings, exact-confirmation revocation, and replacement links. UI wording remains honest: for example, "Asha's link was viewed," never "Asha viewed it."
- Added a metadata-only employee credential catalog with assigned-email identities, passwordless one-time-code sign-in, scoped employee requests, approval and denial controls, break-glass requests, and delivery audit trails. Employee routes never return raw credential values.
- Added Ente Paste as an experimental manual-handoff option. It intentionally reports `handoff_pending` only, because the public provider surface does not supply WardSen with sender-visible view, revoke, or device attribution data.
- Improved Bitwarden onboarding across Windows and macOS: missing-CLI guidance, provider install detection, isolated profile handling, memory-only terminal session handoff, and macOS path resolution before any master-password prompt.
- Made provider-profile paths resistant to overlap and links/reparse points, preserving account separation while retaining existing account metadata during update-path migration.
- Made delivery creation crash-safe with operation records, idempotency keys, reconciliation, restart-safe refusal to recreate a completed one-time URL, and Bitwarden Send operation-marker lookup.
- Added one-time URL copy feedback and tightened operational UI states so destructive actions are explicitly confirmed instead of firing on a single click.
- Expanded release engineering with clean-checkout tag enforcement, per-platform SBOMs, checksum manifests, packaged-server crash/restart smoke evidence, artifact attestation subjects, and provenance evidence validation.
- Added an opt-in disposable-account Bitwarden Send integration test and a macOS testing handoff for live provider, crash-recovery, and signed-DMG lifecycle verification.
- Corrected the npm workspace lockfile so clean GitHub Actions installs include the experimental Ente Paste delivery package.
- Generate release SBOMs from the committed lockfile, avoiding runner-specific workspace-link resolution during cross-platform release builds.
- Corrected the Fastify dependency overrides so SBOM generation keeps Fast JSON Stringify on its required `fast-uri` 4.x line while retaining AJV's compatible 3.x line.

## Known Limits

- Bitwarden Send link access is recipient-link attribution, not verified proof of the human, IP address, device, or user agent that opened it.
- The opt-in live Bitwarden test and signed installed-app lifecycle checks still require execution on a target machine.
- This prerelease is unsigned. Do not treat it as a generally trusted public installer.
