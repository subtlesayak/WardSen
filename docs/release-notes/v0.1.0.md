# WardSen v0.1.0-rc.57

`v0.1.0-rc.57` is an unsigned security-review prerelease. It focuses on making Bitwarden terminal login easier in packaged desktop builds and adding auditable delivery access-code support for employee request links. It is not a trusted end-user macOS release.

## Install Or Update

Download the matching installer and `SHA256SUMS-*.txt` file from the GitHub release and verify the checksum before installation.

- **Windows:** the MSI is an unsigned review artifact. Treat SmartScreen or Defender blocks as a release issue; do not override them for normal use.
- **macOS:** the DMG is an unsigned review artifact. There is no supported end-user workaround for a `cannot be verified` or `is damaged` warning. Do not use `xattr`, `sudo xattr`, or disable Gatekeeper. A signed and notarized DMG is required for normal use.

For Bitwarden, use the official [`bw` CLI](https://bitwarden.com/help/cli/). On macOS, an npm user-owned prefix is supported: WardSen detects `~/.local/bin/bw` after you install the CLI there and reopen the app.

## Changes

- WardSen desktop now opens the Bitwarden terminal login command automatically in PowerShell on Windows or Terminal on macOS.
- Terminal launch uses a server-issued opaque launch ID. The desktop app fetches the one-time command through the trusted local session and validates that it is WardSen's own Bitwarden handoff command before opening a shell.
- Manual **Copy terminal command** remains available when automatic terminal launch is unavailable.
- Employee request fulfillment and replacement links can issue a generated WardSen delivery access code when the selected delivery provider supports access-password enforcement.
- Delivery metadata records whether an access code was required, when it was issued and when provider status first observed access to a code-protected link.
- Vault and account-access layouts wrap more cleanly on narrow screens, and mutating API calls without a body now send `{}` consistently.

## Trusted Release Gate

Before offering WardSen as a normal macOS installer, configure Apple Developer ID signing and notarization secrets plus `MACOS_SIGNING_ENABLED=true`, run the release workflow, and verify the resulting DMG with `codesign`, `spctl`, and `xcrun stapler validate`. See the [installer signing guide](../installer-signing.md) and [release checklist](../release-security-checklist.md).
