# WardSen v0.1.0-rc.58

`v0.1.0-rc.58` is an unsigned security-review prerelease. It focuses on making WardSen's desktop-launched Bitwarden terminal handoff easier to understand and diagnose. It is not a trusted end-user macOS release.

## Install Or Update

Download the matching installer and `SHA256SUMS-*.txt` file from the GitHub release and verify the checksum before installation.

- **Windows:** the MSI is an unsigned review artifact. Treat SmartScreen or Defender blocks as a release issue; do not override them for normal use.
- **macOS:** the DMG is an unsigned review artifact. There is no supported end-user workaround for a `cannot be verified` or `is damaged` warning. Do not use `xattr`, `sudo xattr`, or disable Gatekeeper. A signed and notarized DMG is required for normal use.

For Bitwarden, use the official [`bw` CLI](https://bitwarden.com/help/cli/). On macOS, an npm user-owned prefix is supported: WardSen detects `~/.local/bin/bw` after you install the CLI there and reopen the app.

## Changes

- Windows PowerShell and macOS Terminal now print a short WardSen message before starting Bitwarden login, reminding users to type their password only if Bitwarden prompts.
- The launched terminal window now stays open after the handoff command finishes so users can read successful handoff, Bitwarden, setup, or error messages.
- Windows handoff commands are wrapped before PowerShell encoding, so the visible guidance and the Bitwarden command run in the same console session.
- Windows now retains the new console's standard input, output and error handles so Bitwarden prompts and setup errors render instead of opening a blank terminal window.
- macOS handoff commands now return to a login shell after the command completes, keeping the Terminal window available for review.
- Added Rust unit coverage and Tauri config assertions for both terminal wrapper paths.

## Trusted Release Gate

Before offering WardSen as a normal macOS installer, configure Apple Developer ID signing and notarization secrets plus `MACOS_SIGNING_ENABLED=true`, run the release workflow, and verify the resulting DMG with `codesign`, `spctl`, and `xcrun stapler validate`. See the [installer signing guide](../installer-signing.md) and [release checklist](../release-security-checklist.md).
