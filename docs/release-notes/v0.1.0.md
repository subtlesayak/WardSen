# WardSen v0.1.0-rc.34

Unsigned prerelease with Bitwarden Send unlock preflight help.

Windows installers were pulled from this release after Microsoft Defender flagged the unsigned Windows setup EXE as `Trojan:Win32/Wacatac.B!ml`. Do not restore or run the removed Windows EXE/MSI. Use the macOS artifact only, or build from source while the Windows package is investigated.

## Install Or Update

Windows:

1. Do not install the removed `v0.1.0-rc.34` Windows setup EXE or MSI.
2. If Defender quarantined the file, leave it quarantined or removed.
3. Wait for a new Windows release candidate after the package investigation, or build from source if you are a developer.

macOS:

1. Download the macOS DMG from this release's assets.
2. Open the DMG.
3. Drag WardSen into Applications.
4. Open WardSen from Applications.
5. If macOS says `"WardSen" is damaged and can't be opened`, keep WardSen in Applications, open Terminal, and run `xattr -dr com.apple.quarantine /Applications/WardSen.app`. If Terminal prints `Operation not permitted`, run the same command with `sudo`.

Provider setup:

1. Install the provider tool you want to use, such as Bitwarden CLI `bw` or KeePassXC.
2. If WardSen cannot find the tool, use the install button and copyable help shown in the app.
3. For Bitwarden first login, use **Terminal login**, then return to WardSen and select **Unlock from terminal session**.

Optional verification:

1. Download the matching `SHA256SUMS-macos-arm64.txt` asset.
2. Compare the macOS DMG checksum before opening the DMG.

## Changes

- Bitwarden Send delivery now checks whether the selected delivery account is unlocked before running `bw send`.
- If the delivery account is not logged in, WardSen now shows a clear **Bitwarden Send account needs unlock** message instead of the raw `You are not logged in` CLI failure.
- The help directs users back to **Vaults > Account Access** and **Unlock from terminal session** before creating the secure link.
