# WardSen v0.1.0-rc.50

`v0.1.0-rc.50` is an unsigned security-review prerelease. It includes the desktop recovery and Bitwarden CLI discovery fixes below, but it is not a trusted end-user macOS release.

## Install Or Update

Download the matching installer and `SHA256SUMS-*.txt` file from the GitHub release and verify the checksum before installation.

- **Windows:** the MSI is an unsigned review artifact. Treat SmartScreen or Defender blocks as a release issue; do not override them for normal use.
- **macOS:** the DMG is an unsigned review artifact. There is no supported end-user workaround for a `cannot be verified` or `is damaged` warning. Do not use `xattr`, `sudo xattr`, or disable Gatekeeper. A signed and notarized DMG is required for normal use.

For Bitwarden, use the official [`bw` CLI](https://bitwarden.com/help/cli/). On macOS, an npm user-owned prefix is supported: WardSen now detects `~/.local/bin/bw` after you install the CLI there and reopen the app.

### macOS Bitwarden CLI Permission Error

If `npm install -g @bitwarden/cli` reports `EACCES`, configure npm to use your own home directory instead of using `sudo`:

```bash
mkdir -p "$HOME/.local/bin"
npm config set prefix "$HOME/.local"
grep -qxF 'export PATH="$HOME/.local/bin:$PATH"' "$HOME/.zprofile" || printf '\nexport PATH="$HOME/.local/bin:$PATH"\n' >> "$HOME/.zprofile"
source "$HOME/.zprofile"
npm install -g @bitwarden/cli
bw --version
```

Fully quit and reopen WardSen after the CLI installation. Enter master passwords, MFA codes, and session tokens only in the visible official Bitwarden CLI prompt.

### Legacy Force Quit Recovery

If an older `rc.49` build shows an untrusted desktop-session message after Force Quit, run this diagnostic in Terminal:

```bash
lsof -nP -iTCP:4777 -sTCP:LISTEN
```

Only end the listed process after confirming it is WardSen's old local Node service, then reopen WardSen. `rc.50` selects a fresh local port for every launch, so it does not reuse a stale process on port 4777.

## Changes

- Fixed recovery after Force Quit: each desktop launch selects its own trusted loopback port, so an orphaned local service cannot reject the new desktop session.
- Fixed Bitwarden CLI discovery for npm's user-owned prefix on macOS. This applies to vault search, Bitwarden Send, terminal login fallback, and the setup guidance.
- Added test coverage for the dynamic desktop service address and the `~/.local/bin/bw` resolution path.

## Trusted Release Gate

Before offering WardSen as a normal macOS installer, configure Apple Developer ID signing and notarization secrets plus `MACOS_SIGNING_ENABLED=true`, run the release workflow, and verify the resulting DMG with `codesign`, `spctl`, and `xcrun stapler validate`. See the [installer signing guide](../installer-signing.md) and [release checklist](../release-security-checklist.md).
