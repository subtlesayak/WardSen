# WardSen v0.1.0-rc.60

`v0.1.0-rc.60` is an unsigned security-review prerelease. It includes the rc.59 delivery-state, operation-preview and diagnostics work, plus a macOS release-test clock correction. It is not a trusted end-user macOS release.

## Install Or Update

Download the matching installer and `SHA256SUMS.txt` file from the GitHub release and verify the checksum before installation.

- **Windows:** the MSI is an unsigned review artifact. Treat SmartScreen or Defender blocks as a release issue; do not override them for normal use.
- **macOS:** the DMG is an unsigned review artifact. After verifying the checksum and dragging a known WardSen review copy to Applications, reviewers may run `xattr -dr com.apple.quarantine /Applications/WardSen.app` in Terminal. This temporary quarantine removal is not code signing or notarization; a signed and notarized DMG is still required for normal use.

For Bitwarden, use the official [`bw` CLI](https://bitwarden.com/help/cli/). On macOS, an npm user-owned prefix is supported: WardSen detects `~/.local/bin/bw` after you install the CLI there and reopen the app.

## Changes

- Reissued rc.59 after correcting a test that relied on a timestamp which could become past-due during a macOS GitHub Actions run. The release checks now use a future time relative to the runner while still verifying local expiry reconciliation.
- People Directory now has a visible **Import CSV** action that opens the CSV paste area in place. Export remains available once in the directory filters.
- Delivery Audit no longer calls Bitwarden Send deliveries failed merely because their vault is locked. It reports them as waiting for the named vault to be unlocked and automatically checks again after unlock.
- Audit cards now name their provider and distinguish a verified zero access count from a provider that does not offer sender-visible access telemetry.
- Active and viewed deliveries now become **Expired** from their recorded expiry time even when provider status cannot be refreshed. WardSen does not claim that expiry was observed from the provider in that case.
- Provider Capabilities no longer shows a stale connection-check result after the selection changes.
- Destructive account, person, delivery, batch-link, and batch-cancellation actions now show an impact preview of affected people, credential resources, providers, and active delivery count before exact confirmation is accepted. Person offboarding is now server-confirmed as well.
- Provider Capabilities can now refresh local diagnostics for the selected provider: CLI availability/version, configuration or vault state, linked accounts, capabilities, and link-preview risk. It never displays environment values or provider credentials.
- A generated `WARD-SEN-CANARY-...` adversarial test proves a provider error that echoes credential text is redacted before API/audit/diagnostic output and SQLite persistence. CI and installer builds scan built web and service artifacts before release.

## Trusted Release Gate

Before offering WardSen as a normal macOS installer, configure Apple Developer ID signing and notarization secrets plus `MACOS_SIGNING_ENABLED=true`, run the release workflow, and verify the resulting DMG with `codesign`, `spctl`, and `xcrun stapler validate`. See the [installer signing guide](../installer-signing.md) and [release checklist](../release-security-checklist.md).
