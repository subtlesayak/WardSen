# WardSen v0.1.0-rc.41

Unsigned prerelease with release provenance hardening, API contract checks and cleaner desktop-session recovery diagnostics.

The previous unsigned Windows setup EXE was pulled after a Microsoft Defender `Trojan:Win32/Wacatac.B!ml` machine-learning detection. This release does not publish that NSIS setup EXE. Windows testers get an unsigned MSI only.

## Install Or Update

Windows:

1. Download `WardSen_0.1.0_x64_en-US.msi` from this release's assets.
2. Verify the checksum with `SHA256SUMS-windows-x64.txt`.
3. Run the MSI only if you trust this unsigned prerelease.
4. If Microsoft Defender blocks the MSI, leave it quarantined and report the detection details.

macOS:

1. Download the macOS DMG from this release's assets.
2. Open the DMG.
3. Drag WardSen into Applications.
4. Open WardSen from Applications.
5. If macOS says `"WardSen" is damaged and can't be opened`, keep WardSen in Applications, open Terminal, and run `xattr -dr com.apple.quarantine /Applications/WardSen.app`. If Terminal prints `Operation not permitted`, run the same command with `sudo`.

Provider setup:

1. Install the provider tool you want to use, such as Bitwarden CLI `bw` or KeePassXC.
2. If WardSen cannot find the tool, use the install button and copyable help shown in the app.
3. For Bitwarden first login, use **Terminal login**, then return to WardSen and select **Unlock from terminal session**.

Optional verification:

1. Download the matching `SHA256SUMS-*.txt` asset.
2. Compare the installer checksum before opening the installer.

## Changes

- Windows release packaging now builds and uploads MSI only; the NSIS setup EXE is not produced for this release.
- Public prerelease publishing now allows unsigned MSI validation assets, while final public releases still require signing readiness checks.
- RC release builds now keep the MSI package version numeric while preserving the full RC tag in WardSen release metadata.
- Release builds now include a JSON release manifest alongside SHA-256 checksum files.
- Checksum generation now fails closed if default bundle output mixes stale and fresh installer timestamps.
- Maintainers now have a repeatable web smoke command for desktop and mobile screenshots before shipping.
- GitHub Actions release jobs now pin third-party actions, verify the release tag checkout, and embed release SHA/build timestamp metadata into the desktop UI.
- Public final-release publishing now requires signing readiness checks; unsigned prerelease validation builds remain supported.
- Desktop API token mismatch errors now keep service process/port/runtime diagnostics readable instead of showing a wall of raw local-service JSON logs.
- Web/API delivery responses now pass through shared contract parsers before being used by the UI.
- Provider and release engineering tests now cover executable resolution, provider manifests/conformance, secret non-persistence and release artifact manifests.
- Bitwarden and KeePassXC credential reads now preserve real secret fields for internal delivery payloads while keeping provider errors redacted.
- Fixes Bitwarden Send links that displayed `Password: [REDACTED]` instead of the actual credential password.
- Bitwarden Send now runs `bw send` against the same isolated WardSen account profile used by Vaults.
- Fixes the case where Vaults showed a Bitwarden account as **Unlocked**, but creating a secure link still failed with `You are not logged in`.
- Bitwarden Send delivery now checks whether the selected delivery account is unlocked before running `bw send`.
- If the delivery account is not logged in, WardSen now shows a clear **Bitwarden Send account needs unlock** message instead of the raw `You are not logged in` CLI failure.
- The help directs users back to **Vaults > Account Access** and **Unlock from terminal session** before creating the secure link.
